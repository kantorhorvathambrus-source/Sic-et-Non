Every count here was walked from the repository or read off a tool's own
output; where a fact cannot be established from inside this environment, it

### How developed each language is

`en` and `hu` are structurally identical — `hu` is a full translation of the
English files, not an abridgement. That identity was verified file by file
during translation and is visible in the per-topic counts below, but it is not
fully enforced by a tool: `scripts/verify-quotes.mjs` checks cross-locale
agreement on bibliography URLs, bibliography authors, the presence of
`quote.original` under every translated quotation, and who raises each
objection — it does not compare argument and variant inventories across
locales. The Zod schema in `src/content.config.ts` enforces the per-file shape
rules (variant symmetry, `landsOn`, the paraphrase disclaimer, no
`title-only`) in every language.

### Verification breakdown

Across all 43 content files (20 `en` + 20 `hu` + 1 each in `es`, `fr`, `de`):
**310 quotation slots — 0 primary, 282 corroborated, 28 paraphrase.**

Within `en` (140 slots): 126 `corroborated`, 14 `paraphrase`, 0 `primary`.
`hu` is the same 126 / 14 / 0. `es`, `fr` and `de` are 10 / 0 / 0 each.

`sawWhat` records how much of the source was literally in front of us. Across
the English 140: **`snippet` 137, `abstract` 3, `full-text` 0.** The schema
rejects `title-only` outright, so no quotation on this site rests on a title.

**Primary-source verification is at zero across the board, in every language,
for every quotation.** The reason is the build environment: web *search* works,
web *fetch* does not — the egress proxy blocks page retrieval. So a quotation's
wording can be seen in search result snippets from several independent hosts,
which is what `corroborated` means, but nobody has opened the source and read
the sentence in place, which is what `primary` would mean. Every page states
this to the reader rather than leaving it implied
(`quote.verification.corroborated.note` in `src/i18n/*.json`).

`corroborated` covers a wide range, and `AUDIT.md` classifies the English 140
by what the cited source actually is:

| Source class | Quotations |
|---|---|
| primary text, freely published | 28 |
| author's own site or paper | 30 |
| journal, encyclopedia or scholarly index | 30 |
| publisher, institution or organisation page | 44 |
| quotation aggregator only | 8 |

The last row is the weak one, because aggregators copy each other and four
agreeing hits can be one upstream string. `AUDIT.md` names all eight
individually: Ehrman on topic 13 (Wikiquote); Holland, Weinberg, Harris and
Hitchens on topic 18 (Goodreads and Wikiquote); Coyne twice and Dawkins once on
topic 19 (Goodreads).

## 2. Structural and design state

The whole site is 101 routes, built as 106 HTML files (101 plus five 404
pages). The 101: five home pages, five about pages, five search pages, 43 topic
pages and 43 argument-map pages. `src/lib/routes.ts` is the single route table;
the catch-all `src/pages/[...path].astro` and `sitemap.xml.ts` both build from
it, and `scripts/seo-check.mjs` fails if the sitemap and `dist/` disagree in
either direction.

**Home page.** Title, tagline, one-paragraph lede, a link to the about page,
then the twenty topics grouped under their six category headings, each row
carrying a zero-padded number, the title, and a status tag. A topic without
content in the current language renders as inert text with a "not written yet"
label instead of a link — `home.comingSoon`, translated in all five locales.

**Topic page anatomy**, in render order (`src/components/pages/TopicPage.astro`):
breadcrumb eyebrow (back link / category / number); title; status tag with a
sentence saying what that tag means; layered reading time ("summary" and "full"
minutes, counted over collapsed and expanded prose separately); a link to the
argument map; the "real question" panel; the settled-core panel on the three
topics that have one; distinctions; the two side columns; per argument a claim,
an explanation, a quotation, and a counter (objection plus response) with the
objection labelled by who raises it; variants nested under arguments, each with
a label, a one-line summary, a fuller summary, a "what this changes about the
objection" line, and optionally its own quotation and its own objection; then
notes, "where it stands", "the common mistake", the glossary and the sources
list.

Progressive disclosure is `<details>`/`<summary>`, so everything is in the DOM:
keyboard-reachable, printable and indexed by Pagefind whether open or shut.

**The four Christian positions on topic 6** are not a separate block any more.
They are the `mechanism-not-author` argument (evolutionary creation, carrying
the Dobzhansky quotation) plus its three variants — young-earth creationism,
old-earth creationism, intelligent design. The older `context` block that used
to hold them is **dead code**: `ContextEntry.astro` is still imported and
rendered at `TopicPage.astro:153`, and **zero of the 43 content files carry a
`context` key**. Nothing renders it; nothing fails because of it.

**Language switcher.** All five languages are always linked, because a missing
link is worse than an honest one. A language that carries the current topic
keeps the reader's place — the same topic, and the URL hash survives, because
argument ids are identical across all five files. A language that does not gets
the `untranslated` class, an `abbr title` that names the language and says it is
untranslated, and visually-hidden text saying the same for screen readers; the
link lands on that language's home page.

**Search.** Pagefind 1.5.2, one index per language, 96 pages indexed (the 101
routes minus the five search pages, which carry no `data-pagefind-body`).
`npm run check:search` drives a real browser against each locale and asserts the
results stay in language. Latest run: `/search/` "suffering" → 2 results,
`/es/buscar/` "evolución" → 7, `/fr/recherche/` "évolution" → 7, `/de/suche/`
"Evolution" → 3, `/hu/kereses/` "teremtés" → 11, all in-language.

**Glossary tooltips.** A term is a real `<dfn tabindex="0">` with the definition
as an in-DOM `<span role="note">`, so it is reachable by keyboard and by screen
reader, not a `title` attribute. Two bugs were found and fixed (commit
`2725777`):

1. The closed definition was `visibility: hidden`, which still takes part in
   layout. Absolutely positioned at the term's left edge with a
   viewport-relative width, it pushed **every topic page in every locale and
   both themes into horizontal scroll at 375px** before anyone touched a term.
   It is `display: none` now.
2. Fixing that exposed a second, older bug: an *open* definition could run off
   the right edge, because it hangs from a term that may sit near the end of a
   line. Ten of forty-three terms did this at 1280px. Below 40rem it is now a
   pinned `position: fixed` sheet; above that, a script measures on
   `mouseenter`/`focus` and sets `data-flip="left"` so the box hangs from the
   right. With JavaScript off, `max-width: min(22rem, calc(100vw - 2.5rem))`
   still holds it inside the window.

**Dark mode.** System preference by default via `prefers-color-scheme`, with an
explicit three-state toggle writing `data-theme` on `:root` and an inline script
that applies the stored choice before first paint, so there is no flash. Every
colour rule is declared for both the media query and the explicit attribute.
`npm run check:palette` asserts the two side accents keep their OKLCH
invariants and their measured contrast (light 7.11:1 / 6.43:1, dark 10.35:1 /
11.03:1, floor 4.5:1).

**Responsive behaviour.** Breakpoints at 52rem, 40rem and 32rem.
`npm run check:layout` renders all 106 pages at 360, 768 and 1280px in both
themes with disclosures collapsed and expanded — 1032 renders — and measures
real glyph advances rather than estimating. Current state: no running text under
180px, none past 95 characters per line, nothing below 4.5:1. The measured band
across both typefaces and all five languages is 28 to 79 characters.

**Accessibility.** `npm run audit` runs axe-core over 106 pages × light/dark ×
collapsed/expanded — **344 runs, zero violations.** Lighthouse (mobile
emulation, local server) on five representative routes:

| Route | Perf | A11y | Best practices | SEO |
|---|---|---|---|---|
| `/` | 98 | 100 | 100 | 100 |
| `/topics/problem-of-suffering/` | 96 | 100 | 100 | 100 |
| `/about/` | 98 | 100 | 100 | 100 |
| `/hu/temak/teremtes-vagy-evolucio/` | 90 | 100 | 100 | 100 |
| `/search/` | 94 | 100 | 100 | 100 |

The performance column is the least trustworthy number in this document: a local
server has no latency, no CDN and no compression, and these figures move a few
points run to run. They have never been measured against a real origin, because
there is not one — see section 3.

## 3. Technical and deployment state

**Framework.** Astro 5.18.2 (`package.json` pins `^5.14.1`), TypeScript 5.9, no
UI framework integration at all. Content is Astro content collections with a Zod
schema and a `superRefine` in `src/content.config.ts` that enforces the content
rules at build time. `npm run check` (`astro check`) currently reports 45 files,
0 errors, 0 warnings, 0 hints. `.nvmrc` pins Node 22; `engines.node` is
`>=20.3.0`.

**Pages → Workers migration.** The project used to carry a Pages-style
`wrangler.toml` with `pages_build_output_dir`. That had to go: the Cloudflare
dashboard's Git-integration flow runs `wrangler deploy`, and `wrangler deploy`
does not accept a Pages config — it wants a Workers config and, by default, a
Worker entry point. The replacement is `wrangler.jsonc`:

```jsonc
{
  "name": "sic-et-non",
  "compatibility_date": "2026-09-18",
  "assets": {
    "directory": "./dist",
    "not_found_handling": "404-page",
    "html_handling": "auto-trailing-slash"
  }
}
```

There is deliberately no `main` (assets-only project, no Worker script) and no
binding of any kind. `public/_headers` survives the migration: `_headers` and
`_redirects` are supported natively by Workers static assets as long as they sit
inside the asset directory, which `dist/_headers` does. The CSP there is
`default-src 'self'` with no external origin at all — fonts, the search index,
the search runtime and its wasm are all same-origin.

**Environment variables.** The site reads none at runtime; it is static files
with no backend and no key. One matters at build time: **`SITE_URL`**, because
canonical URLs, `hreflang`, `og:url`, `sitemap.xml` and `robots.txt` all derive
from Astro's `site` and a wrong origin poisons all five at once. Workers Builds
injects no URL variable — it sets `CI`, `WORKERS_CI`, `WORKERS_CI_BUILD_UUID`,
`WORKERS_CI_COMMIT_SHA` and `WORKERS_CI_BRANCH` and nothing else, and a Worker's
hostname is `<name>.<account-subdomain>.workers.dev`, which this repository
cannot know. So `astro.config.mjs` throws when `WORKERS_CI=1` and `SITE_URL` is
unset, rather than shipping a site whose every URL is internally consistent and
uniformly wrong. `scripts/seo-check.mjs` additionally fails when `robots.txt`
and the sitemap name different origins — the shape of a half-finished domain
change. Neither guard can catch an origin that is wrong but consistent.

**404 handling.** Two halves, both needed. Astro's directory build format writes
localised 404s as `dist/es/404/index.html`, special-casing only the root one, so
the `localised404s` integration in `astro.config.mjs` moves each to
`dist/<lang>/404.html`. Cloudflare then has to be told to serve them at all:
`assets.not_found_handling: "404-page"` serves the *nearest* `404.html` walking
up from the requested path, so `/hu/anything` answers in Hungarian. The default
for static assets is a bare `404 Not Found` with no page, so dropping that one
line would silently throw away all five localised 404s. `dist/` currently
contains `404.html` plus `de/`, `es/`, `fr/` and `hu/404.html`.

**What `npm run milestone` checks**, in order: `astro check` (types) → content
rules (`verify-quotes.mjs`) → build → Pagefind index → internal link and anchor
check → layout, measure and contrast → palette invariants → typographic style →
SEO, canonicals, hreflang and sitemap → live in-browser search in five locales →
axe-core plus Lighthouse → regenerate `AUDIT.md` → regenerate `VERIFICATION.md`.

**Current state: green, end to end.** Last full run: 106 pages, 2064 internal
links and 262 distinct external URLs (external not fetched), all internal links
and anchors resolving; 1032 layout renders clean; palette, style and SEO passing
over 101 pages; search passing in all five locales; 344 axe runs with zero
violations; `AUDIT.md` regenerated at 20 topics / 140 quotations / 14
paraphrases / 8 on aggregators; `VERIFICATION.md` regenerated at 140 quotations,
0 verified.

**Is it deployed? No. There is no live URL.**

`npx wrangler deploy --dry-run` is clean: wrangler 4.135.0 reads 378 files from
`./dist`, reports "No bindings found" and exits 0 without contacting Cloudflare.
So the configuration is right up to the authentication step. The real deploy
cannot run from here: there is no `CLOUDFLARE_API_TOKEN` in the environment, and
the shell is non-interactive, so `wrangler login` is impossible. Nothing about
the site's behaviour on Cloudflare has been observed — only what Cloudflare's
documentation says it will do.

One consequence is visible in the tree right now: with no `SITE_URL` set, the
origin falls back to the literal in `astro.config.mjs`, so **every canonical
URL, every `hreflang`, the whole of `dist/sitemap.xml` and the `Sitemap:` line
in `dist/robots.txt` currently point at `https://sic-et-non.pages.dev`, a host
that is not serving this site.** That is correct behaviour for a local build and
would be a live defect; the fix is one build variable, and `DEPLOY.md` says so.

## 4. Known integrity issues and deliberate non-fixes

**Fixed: a misattribution.** In all four non-English copies of topic 6, the
Answers in Genesis *Statement of Faith* was credited to John C. Whitcomb and
Henry M. Morris. The `sources[]` author values had shifted by one row during
translation, so two real people were named as authors of a document they did not
write. It was found by printing the complete diff rather than trusting a filter
— the first two detection filters both missed it, one with false positives and a
miss on `Tomás de Aquino`, the other because the row's copy was translated (`és`,
not `and`). Fixed in commit `9caebf8`.

**Fixed: the gap that let it through.** A bibliography was the one place on this
site where a name was not being checked. `scripts/verify-quotes.mjs` now fails
on any translated `sources[]` author that is neither the English name nor a
registered localisation of it, and it keeps every English row per URL so topic
7, which cites one page twice on purpose, still passes.

**Fixed: five undercounts of the same shape.** `verify-quotes.mjs` was not
validating or counting variant quotations at all — the site reported 114
quotations while carrying 155, and 6 paraphrases where there were 11. The
reading-time counter walked variant prose but not variant objections. The
verification worksheet filtered paraphrases on a regex that only matched main
slots, hiding 5 of 13. Every one of these read *lower* than the truth. This is
why `AUDIT.md` exists and why nothing in it is counted by eye.

**Unfixed, deliberate, and the most user-visible problem in this document:
the home page overclaims how the quotations were sourced.** `home.intro` in
`src/i18n/en.json` — rendered at `src/components/pages/HomePage.astro:45` —
reads:

> Twenty questions people argue about. On each one you get the best case for
> both sides, **in the words of the people who made it.** The site never tells
> you who won.

For 126 of 140 English slots that is true. For the other 14 it is not: those are
paraphrases in our words, and the reader is told so *on the topic page* but not
here. `site.description` in the same file makes the stronger claim — "…with **real
quotations** from the thinkers who made them" — and it is the
`<meta name="description">` of the five home pages and the `og:image:alt` on all
101. Both lines exist in all five locale files
(`src/i18n/{en,es,fr,de,hu}.json`, same two keys). This is left unfixed because
correcting one sentence in five languages is a content decision about the site's
own voice, not a bug fix, and it should be made deliberately rather than
smuggled into a translation commit.

**Unfixed: name-form inconsistencies.** The guard added in `9caebf8` enforces
one form per person *per file*, which is what a bibliography needs. It does not
look across files, and it does not compare `quote.author` against `sources[]`
within a file. Five cases survive, all of them real:

| Person | Form A | Form B |
|---|---|---|
| Daniel Dennett | `Daniel Dennett` (topic 6 `quote.author`, all 5 locales) | `Daniel C. Dennett` (topic 6 `sources[]`, all 5 locales; and throughout topic 9) |
| Douglas Axe | `Douglas Axe` (topic 7 `quote.author`, en + hu) | `Douglas D. Axe` (topic 7 `sources[]`, en + hu) |
| Powner / Gerland / Sutherland | without middle initials (topic 7 variant quote) | `Matthew W. Powner … John D. Sutherland` (topic 7 `sources[]`) |
| C. S. Lewis | `C. S. Lewis` (topic 4) | `C.S. Lewis` (topic 12) |
| J. L. Mackie | `J. L. Mackie` (topic 15) | `J.L. Mackie` (topic 10) |

The first three are within-file `quote.author` vs `sources[]` splits; the last
two are cross-topic spacing differences. None is a misattribution — every form
names the right person — but the Whitcomb/Morris incident started as a
formatting-level slip too, and the honest description is that the guard is
narrower than the problem.

**Unfixed: no RSS or Atom feed.** `dist/` contains no `rss.xml`, `feed.xml` or
equivalent, and nothing in the repository generates one. Whether that matters
depends on whether the site is meant to be followed or only visited; that is a
product decision nobody has made.

**Unfixed: a dead render path.** `ContextEntry.astro` is imported and rendered
by `TopicPage.astro`, and no content file carries a `context` key. Harmless, but
it is a component maintained for no caller.

**Unfixed, and deliberate: zero primary verification.** Nothing here can raise a
quotation above `corroborated`, so nothing pretends to. The alternative — marking
things `primary` on the strength of agreeing snippets — is the failure mode this
whole apparatus exists to prevent.

**A process note, because it cost real time.** One falsification test in this
project silently passed while proving nothing: an attempt to corrupt
`dist/robots.txt` replaced a string that a previous build had already changed,
so the edit was a no-op and the "failing" check never ran. A falsification is
only evidence if you confirm it actually changed something first.

## 5. If I had to pick three things to do next

**1. Deploy it, then rebuild with the real origin.** Everything else in this
document is about a site nobody can visit. The configuration is verified clean
up to authentication; what is missing is a credential and one build variable.
Until `SITE_URL` is set to the origin that actually serves the site, the sitemap,
every canonical and every `hreflang` point at `sic-et-non.pages.dev`, and the
Lighthouse performance numbers above are measurements of a localhost server.
This is the only item that changes whether the project exists for anyone.

**2. Fix the two sourcing sentences, then clear the fourteen paraphrases.** The
home pages and their `<meta>` descriptions claim the arguments come
in their authors' own words; for 14 of 140 slots they do not. That is the one
place where the site's own copy is less careful than its content, and on a
project that treats a misattribution as a serious failure, an overclaim in the
lede is the same category of error at larger scale. Rewriting two sentences is
an hour. Retiring the paraphrases behind them is longer but bounded, and
`VERIFICATION.md` already orders the work: Schellenberg first, because topic 4
is his argument and the page carrying it cannot quote its own author.

**3. Decide about `es`, `fr` and `de`.** Two languages are complete and three
are 5% complete, and the switcher is honest about it on every page — nineteen
"not written yet" rows on three home pages. That is a defensible state to ship
and an indefensible state to leave indefinitely, because it reads as abandonment
rather than as a plan. Either commit to translating them, or cut them to a
single well-made page that says the site is in English and Hungarian and links
to both. The current middle is the only option that costs something and buys
nothing.

Two things I considered and left off: the name-form inconsistencies (real, but
no reader is misled, and the fix is mechanical whenever someone touches those
files) and the RSS feed (cheap, but nobody has established that anyone wants to
follow this site).
